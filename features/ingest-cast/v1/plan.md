# Plan: ingest-cast v1 — Post-Sync Cast Transforms

## Overview

After an Airbyte sync, raw tables often land with incorrect column types (e.g., numeric amounts as `STRING`). Downstream dbt transforms then need explicit casts in every model. This feature lets users configure column type casts per stream in the connection modal; the backend pre-generates dialect-specific SQL; Prefect executes it immediately after each sync, in-place on the raw table.

**Services affected:** DDP_backend, webapp_v2, prefect-proxy, prefect-airbyte (Dalgo fork)

---

## Architecture Revision — Nov 2026 (M5)

The original design (M1-M4 below) stored the pre-generated cast SQL inside **Prefect deployment parameters**, embedded in the airbyte sync task config. During staging validation three problems surfaced:

1. **Staleness across pipelines** — a connection can belong to multiple pipelines; updating cast config only refreshed the deployment params of one pipeline (`.first()`), leaving the others stale.
2. **Task-list overwrite bug** — the deployment-params update code rewrote `config.tasks` with just the airbyte task, wiping any dbt/git tasks from orchestrated pipelines.
3. **`run_connection_sync` is async** — calling it from a sync `@flow` submitted it as a non-blocking sub-run; the parent returned before the sync finished, so `_run_post_sync_ops` fired before data landed.

**Pivot (M5):** cast SQL now lives on the persisted `AirbyteConnection` **block** itself, in a new `extra: dict` field. All pipelines using that block pick up the latest SQL on their next run — no deployment-param manipulation. The flow is fully async and awaits the sync properly. Post-sync ops run as a separate Prefect `@task` so they surface in the UI.

**Key deltas from original plan:**

| Original design (M1-M4) | Revised design (M5) |
|---|---|
| SQL baked into deployment `task_config.env` + `task_config.post_sync_ops` | SQL saved to `AirbyteConnection.extra["env"/"post_sync_ops"]` on the block |
| `update_connection` rewrites deployment params via `update_dataflow_v1` | `update_connection` upserts the block via `PUT /proxy/blocks/airbyte/connection/` |
| `run_airbyte_connection_flow_v1(payload)` — sync `@flow`, reads `env`/`ops` from payload | Async `@flow`; `AirbyteConnection.aload(connection_id)` then reads `extra` from the block |
| `_run_post_sync_ops` inline (not visible in Prefect graph) | `@task(name="post-sync-ops", retries=0)` — visible in UI graph, uses `get_run_logger()` for logs |
| BigQuery `generate_cast_sql` fetches all live columns via `get_table_columns()` | Backend stores **raw config** in the block; prefect-proxy builds SQL at flow-run time using `bq_client.get_table(...)` to preserve Airbyte's partition/cluster spec |
| SQL generation lives in DDP_backend warehouse clients (`generate_cast_sql` methods) | SQL generation moves to prefect-proxy — closer to where execution happens, uses live metadata (partition/cluster spec, actual column names) |
| Legacy env/ops fields kept on `PrefectAirbyteSyncTaskSetup` | **Removed** — task config carries only server-block + connection_id; block loaded at runtime |
| No migration path noted | **Progressive** — blocks created lazily when user saves a connection with cast config. Existing connections without casts stay on the fallback (inline `AirbyteConnection`, no post-sync ops). No backfill required. |

**Block `extra` shape (final):**
```json
{
  "name": "<connection name>",
  "env": {"dbt-profile-secret-block": "dbt-profile-<slug>"},
  "post_sync_ops": [
    {
      "type": "cast",
      "schema": "dest_schema",
      "table": "stream_name",
      "column_casts": {"col1": "numeric", "col2": "timestamp"}
    }
  ]
}
```

`wtype` is not on each op — proxy reads it from the loaded secret block (single source of truth). Post-sync ops carry pure intent; prefect-proxy is responsible for turning that intent into dialect-specific SQL at execution time.

Detailed LLD for the revision lives in [M5 milestone](#milestone-5-connection-block-based-architecture-revision) below. The M1–M4 sections are retained for historical reference — they describe the original approach that got shipped to staging and validated the end-to-end feedback loop that surfaced the issues above.

## Design Decisions

| Question | Decision |
|---|---|
| SQL operation | ALTER TABLE in-place (Postgres); CREATE OR REPLACE TABLE (BigQuery — cannot ALTER COLUMN TYPE for incompatible casts like STRING→NUMERIC) |
| Warehouse connectivity | Via `dbt_profile_secret_block` Prefect Secret block on `OrgWarehouse` |
| Warehouse scope | Postgres + BigQuery |
| Task architecture | Embedded in airbyte-sync task config — no new OrgTask/Task DB row |
| UI placement | "Cast to" dropdown per column in the expanded stream view |
| SQL timing | Pre-generated by backend at task-config-build time; passed in Prefect task payload |

## High-Level Design

```
User (connection modal)
  → expands stream → sets "Cast to type" per column
  → saves connection

DDP_backend (connection create/update)
  → stores cast spec in OrgTask.post_sync_transform
      {"cast": {"stream_name": [{"columnname": "col", "columntype": "numeric"}]}}
  → when building Prefect task config:
      look up OrgWarehouse.wtype + OrgWarehouse.dbt_profile_secret_block
      look up connection's destinationSchema + all stream column names (Airbyte API)
      generate dialect-specific SQL
      embed SQL + secret block name in PrefectAirbyteSyncTaskSetup

prefect-proxy (sync flow)
  run_airbyte_connection_flow_v1(payload)
    → run_connection_sync(...)       # existing Airbyte sync
    → _run_cast_sql(payload)        # NEW: no-op when cast_sql is empty
        load Secret block → creds
        connect to warehouse (psycopg2 / google-cloud-bigquery)
        execute SQL
```

**SQL generated by backend:**

Postgres:
```sql
ALTER TABLE dest_schema.orders
  ALTER COLUMN amount TYPE numeric USING amount::numeric,
  ALTER COLUMN created_at TYPE timestamp USING created_at::timestamp;
```

BigQuery (no ALTER COLUMN TYPE for incompatible type changes — full table replace):
```sql
CREATE OR REPLACE TABLE `project.dest_schema.orders` AS
SELECT
  id,
  name,
  CAST(amount AS NUMERIC) AS amount,
  CAST(created_at AS TIMESTAMP) AS created_at
FROM `project.dest_schema.orders`;
```

## Low-Level Design

### Data model

**`OrgWarehouse`** (`ddpui/models/org.py`) — new FK:
```python
dbt_profile_secret_block = models.ForeignKey(
    "ddpui.OrgPrefectBlockv1",
    on_delete=models.SET_NULL,
    null=True, blank=True,
    related_name="warehouse_dbt_profile_secret_block",
)
```

**`OrgTask`** (`ddpui/models/tasks.py`) — new field:
```python
post_sync_transform = models.JSONField(null=True, blank=True, default=None)
```

`NULL` means no post-sync operations — task config is emitted with `post_sync_ops: []` and the proxy skips entirely. Never stored as `{}`.

Shape when set:
```json
{
  "ops": [
    {
      "type": "cast",
      "schema": "dest_schema",
      "table": "orders",
      "config": {"amount": "numeric", "created_at": "timestamp"}
    },
    {
      "type": "cast",
      "schema": "dest_schema",
      "table": "customers",
      "config": {"age": "integer"}
    }
  ]
}
```

**Diff rule**: only ops where the user's selected type differs from the column's current type are stored. Columns where the selected type matches the existing type are dropped before saving. If all columns across all streams are no-ops after filtering, `post_sync_transform` is set to `NULL`. This filtering happens on the **frontend** — it has both the original type (from Airbyte stream schema) and the user-selected type, so it can compute the diff before sending. The backend stores whatever arrives; if the payload is empty/null, it writes `NULL`.

### Cast SQL generation — DDP_backend

No new module. SQL generation is added as **static methods** on the existing warehouse clients so dialect logic stays co-located with the client.

**`ddpui/utils/warehouse/client/postgres.py`** — new static method on `PostgresClient`:
```python
@staticmethod
def generate_cast_sql(schema: str, table: str, column_casts: dict[str, str]) -> str:
    """column_casts: {column_name: target_type}
    Returns ALTER TABLE schema.table ALTER COLUMN col TYPE type USING col::type, ...
    Raises ValueError for unknown types."""
```

**`ddpui/utils/warehouse/client/bigquery.py`** — new static method on `BigqueryClient`:
```python
@staticmethod
def generate_cast_sql(
    project_id: str, schema: str, table: str,
    column_casts: dict[str, str],
    all_columns: list[str],
) -> str:
    """column_casts: {column_name: target_type}; all_columns: full column list for SELECT pass-through.
    Returns CREATE OR REPLACE TABLE `project.schema.table` AS SELECT ..., CAST(col AS type) AS col, ...
    Raises ValueError for unknown types."""
```

**`ddpui/utils/warehouse/client/warehouse_factory.py`** — new class method on `WarehouseFactory`:
```python
@classmethod
def generate_cast_sql(
    cls,
    org_warehouse: OrgWarehouse,
    schema: str,
    table: str,
    column_casts: dict[str, str],
    all_columns: list[str] = None,
) -> str:
    """Dispatches to the correct client's generate_cast_sql() based on wtype.
    For BigQuery, retrieves project_id from warehouse credentials."""
    if org_warehouse.wtype == WarehouseType.POSTGRES:
        return PostgresClient.generate_cast_sql(schema, table, column_casts)
    elif org_warehouse.wtype == WarehouseType.BIGQUERY:
        creds = retrieve_warehouse_credentials(org_warehouse)
        return BigqueryClient.generate_cast_sql(
            creds["project_id"], schema, table, column_casts, all_columns
        )
    raise ValueError(f"Unsupported warehouse type: {org_warehouse.wtype}")
```

Type maps live inside each static method (postgres types are lowercase SQL keywords; bigquery types are BigQuery standard SQL names).

### Prefect-proxy — cast execution

**`prefect-proxy/proxy/prefect_flows.py`** — new helper + hook into sync flow:

```python
def _run_post_sync_ops(payload: dict) -> None:
    post_sync_ops = payload.get("post_sync_ops", [])
    if not post_sync_ops:
        return

    block_name = payload.get("env", {}).get("dbt-profile-secret-block")
    if not block_name:
        return

    raw = Secret.load(block_name).get()
    data = json.loads(raw)
    wtype = data["wtype"]
    creds = data["creds"]

    for op in post_sync_ops:
        if op["type"] != "cast":
            continue
        sql = op["sql"]
        if wtype == "postgres":
            import psycopg2  # available via dbt-postgres in pyproject.toml
            conn = psycopg2.connect(
                host=creds["host"], port=creds.get("port", 5432),
                dbname=creds["dbname"], user=creds["username"],
                password=creds["password"],
            )
            conn.autocommit = True
            with conn.cursor() as cur:
                cur.execute(sql)
            conn.close()

        elif wtype == "bigquery":
            from google.oauth2.service_account import Credentials  # available via prefect-gcp
            from google.cloud import bigquery
            credentials = Credentials.from_service_account_info(creds)
            client = bigquery.Client(credentials=credentials, project=creds["project_id"])
            client.query(sql).result()

# In run_airbyte_connection_flow_v1:
#   result = run_connection_sync(connection_block)
#   _run_post_sync_ops(payload)    ← add this line
#   return result
```

Each `post_sync_ops` entry carries one SQL statement (one table). The proxy iterates and executes them sequentially. `type` field enables future op types without changing the loop structure.

## Security Review

- **Auth/Authz**: Gated by existing connection update permissions — no new perms needed
- **SQL injection**: Column names come from Airbyte-fetched schema (not free-form input); cast types validated against `CAST_TYPE_MAP` keys before SQL generation — unknown type → `ValueError` before any SQL is built
- **Credential handling**: Credentials loaded from Prefect Secret block inside the flow only, never in responses or logs
- **Multi-tenancy**: `OrgTask` is org-scoped; `OrgWarehouse` is `unique=True` per org
- **BigQuery project**: Project ID appears in SQL string inside the Prefect task config — acceptable (internal system, not user-facing)

## Testing Strategy

- **Unit — `cast_sql.py`**: 0 columns (no-op), 1 column, N columns, unknown type raises `ValueError`, Postgres dialect, BigQuery dialect
- **Unit — `setup_airbyte_sync_task_config()`**: with and without `post_sync_transform`; verify `cast_sql` / `warehouse_secret_block` / `warehouse_type` in output
- **Unit — `_run_cast_sql()`**: mock `psycopg2.connect` and `bigquery.Client`; verify correct SQL passed; verify no-op on empty `cast_sql`
- **API tests**: connection create/update round-trip with `post_sync_transform`; GET returns stored config
- **E2E (Postgres)**: create connection with cast config → trigger manual sync → `SELECT pg_typeof(amount) FROM schema.orders` returns `numeric`
- **Regression**: existing connection CRUD tests pass with `post_sync_transform` defaulting to `{}`; existing pipeline runs pass without cast config

#### M1.1 — Add `generate_cast_sql()` to warehouse clients

Both methods are **instance methods** (not static) so they can use `self.engine` for identifier quoting and column introspection.

**`ddpui/utils/warehouse/client/postgres.py`** — add instance method to `PostgresClient`:
```python
def generate_cast_sql(self, schema: str, table: str, column_casts: dict[str, str]) -> str:
    """column_casts: {column_name: target_type}, e.g. {"amount": "numeric", "ts": "timestamp"}
    Returns ALTER TABLE schema.table ALTER COLUMN col TYPE type USING col::type, ...
    Returns "" if column_casts is empty. Raises ValueError for unknown types.
    Uses self.engine.dialect.identifier_preparer for safe identifier quoting."""
```

SQL shape:
```sql
ALTER TABLE "schema"."table"
  ALTER COLUMN "amount" TYPE numeric USING "amount"::numeric,
  ALTER COLUMN "created_at" TYPE timestamp USING "created_at"::timestamp
```

Supported types: `numeric`, `integer`, `bigint`, `boolean`, `date`, `timestamp`, `text`

No column introspection needed — just iterates `column_casts`.

**`ddpui/utils/warehouse/client/bigquery.py`** — add instance method to `BigqueryClient`:
```python
def generate_cast_sql(self, schema: str, table: str, column_casts: dict[str, str]) -> str:
    """Fetches all columns via self.get_table_columns() (includes Airbyte meta columns),
    then builds CREATE OR REPLACE TABLE `project.schema.table` AS SELECT with CAST for
    cast columns and pass-through for the rest.
    Returns "" if column_casts is empty. Raises ValueError for unknown types.
    Uses self.engine.dialect.identifier_preparer for safe identifier quoting."""
```

SQL shape:
```sql
CREATE OR REPLACE TABLE `project`.`schema`.`table` AS
SELECT
  `id`,
  `name`,
  CAST(`amount` AS NUMERIC) AS `amount`,
  `_airbyte_raw_id`,
  `_airbyte_extracted_at`
FROM `project`.`schema`.`table`
```

`self.get_table_columns(schema, table)` fetches the live column list from the warehouse — includes Airbyte meta columns (`_airbyte_raw_id` etc.) that are absent from the Airbyte sync catalog. This avoids stale catalog data and column loss.

Supported types: `numeric` → `NUMERIC`, `integer`/`bigint` → `INT64`, `boolean` → `BOOL`, `date` → `DATE`, `timestamp` → `TIMESTAMP`, `text` → `STRING`

def setup_airbyte_sync_task_config(
    org_task: OrgTask, server_block: OrgPrefectBlockv1, seq: int = 1
):
    env = {}
    post_sync_ops = []

    if org_task.post_sync_transform:   # NULL → skip entirely
        org = org_task.org
        try:
            warehouse = OrgWarehouse.objects.filter(org=org).first()
            if warehouse and warehouse.dbt_profile_secret_block:
                warehouse_client = WarehouseFactory.get_warehouse_client(warehouse)

                for op in org_task.post_sync_transform.get("ops", []):
                    if op["type"] != "cast":
                        continue
                    sql = warehouse_client.generate_cast_sql(
                        op["schema"], op["table"], op["config"]
                    )
                    if sql:
                        post_sync_ops.append({"type": "cast", "sql": sql})

                env["dbt-profile-secret-block"] = warehouse.dbt_profile_secret_block.block_name
            else:
                logger.warning(
                    "setup_airbyte_sync_task_config: no dbt_profile_secret_block on warehouse "
                    "for org=%s — post_sync_ops skipped",
                    org.slug,
                )
        except Exception as err:  # pylint: disable=broad-exception-caught
            logger.warning(
                "setup_airbyte_sync_task_config: failed to build post_sync_ops for org=%s: %s",
                org_task.org.slug, err,
            )

    return PrefectAirbyteSyncTaskSetup(
        seq=seq,
        slug=org_task.task.slug,
        type=AIRBYTECONNECTION,
        airbyte_server_block=server_block.block_name,
        connection_id=org_task.connection_id,
        timeout=PREFECT_AIRBYTE_TASKS_TIMEOUT,
        orgtask_uuid=str(org_task.uuid),
        env=env,
        post_sync_ops=post_sync_ops,
    )

#### M3.1 — Implement `_run_post_sync_ops()` (`proxy/prefect_flows.py`)

Add this function near `run_airbyte_connection_flow_v1` (line 52). No new imports needed — `Secret`, `json` are already at the top of the file; `psycopg2` and `google.cloud.bigquery` are available in the venv via `dbt-postgres` and `dbt-bigquery`.

```python
def _run_post_sync_ops(payload: dict) -> None:
    """Execute post-sync warehouse operations (e.g. column type casts).
    No-op when post_sync_ops is empty or secret block is missing."""
    post_sync_ops = payload.get("post_sync_ops", [])
    if not post_sync_ops:
        return

    block_name = payload.get("env", {}).get("dbt-profile-secret-block")
    if not block_name:
        logger.warning("_run_post_sync_ops: no dbt-profile-secret-block in env — skipping")
        return

    raw = Secret.load(block_name).get()
    data = raw if isinstance(raw, dict) else json.loads(raw)
    wtype = data["wtype"]
    creds = data["creds"]

    if wtype == "postgres":
        import psycopg2  # available via dbt-postgres in pyproject.toml
        conn = psycopg2.connect(
            host=creds["host"],
            port=creds.get("port", 5432),
            dbname=creds["database"],   # secret block stores "database" (not "dbname")
            user=creds["user"],          # mapped from "username" by preprocess_airbyte_creds_for_dbt
            password=creds["password"],
        )
        conn.autocommit = True
        try:
            with conn.cursor() as cur:
                for op in post_sync_ops:
                    if op.get("type") == "cast":
                        cur.execute(op["sql"])
        finally:
            conn.close()

    elif wtype == "bigquery":
        from google.oauth2.service_account import Credentials
        from google.cloud import bigquery
        credentials = Credentials.from_service_account_info(creds)
        client = bigquery.Client(credentials=credentials, project=creds["project_id"])
        try:
            for op in post_sync_ops:
                if op.get("type") == "cast":
                    client.query(op["sql"]).result()
        finally:
            client.close()

    else:
        logger.warning("_run_post_sync_ops: unsupported wtype=%s — skipping", wtype)
```

**Creds key notes** (from how the secret block is built by `create_or_update_dbt_profile_secret_blk` + `preprocess_airbyte_creds_for_dbt` in `dbthelpers.py`):
- Postgres: `database` (raw Airbyte destination field name; not renamed), `user` (mapped from Airbyte's `username`), `host`, `port`, `password`
- BigQuery: raw service account JSON, `project_id` at top level

const buildPostSyncTransform = (): PostSyncTransform | null => {

## Open Questions & Risks

1. **`dbt_profile_secret_block` for non-dbt orgs**: Block only exists if dbt was set up. Orgs using Airbyte without dbt will have `OrgWarehouse.dbt_profile_secret_block = null`. MVP: skip cast + log warning. Future: create block at warehouse setup time. UI should note the limitation (tooltip in the cast config section).

2. **BigQuery requires all column names**: `CREATE OR REPLACE TABLE ... AS SELECT col1, CAST(col2) ...` needs the full column list to pass through non-cast columns. These must be fetched from Airbyte's stream catalog at SQL-generation time. If the catalog isn't available, skip cast for that stream + log warning.

3. **Scheduled pipeline staleness**: Cast SQL is baked into Prefect deployment params at create/update time. If the Airbyte source schema changes (new column added), SQL is stale until user re-saves the connection.

4. **`ALTER TABLE` performance on large Postgres tables**: `ALTER COLUMN TYPE USING` rewrites the table. For large tables this can extend sync windows significantly. Document as a known limitation for MVP.

5. **`post_sync_transform` staleness on schema change**: Cast config is stored at connection-save time. If the Airbyte source schema changes (new column added), the stored config is stale until the user re-saves the connection. No auto-refresh — document as a known limitation.

### Milestone 5: Connection-block-based architecture revision

**Why:** Deployment-param-based SQL storage broke on multi-pipeline connections + wiped orchestrated task lists on update (see [Architecture Revision](#architecture-revision--nov-2026-m5) at the top).
